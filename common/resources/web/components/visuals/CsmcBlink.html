Buffers outgoing movement while the server keeps you where you were, and pushes the buffer out the moment an action packet leaves, so the server sees you where you stand before it resolves the shot. Use csmcBlink.enable() / csmcBlink.disable() as keybinds, or toggle Enabled here. While enabled you keep moving on the client only, so everything the server resolves comes from the last released position. Standing still releases what is held once the tick threshold is reached: the stutter comes from movement, not from standing in one place.
Enabled
Buffer movement now. Turning it off releases whatever is held, so the server catches up with where you walked instead of leaving you behind.
Flush On Shot
Release the buffer the moment a shot is being fired, so the server resolves it against the position you are standing in. On weapons that stay on the vanilla attack path the trigger is the action packet itself; on CSMC 6.0, which builds no packet for a shot, it is the fire key being held. Both are watched, so every shot - including the first one of a press - is preceded by its own release. Buffering continues afterwards, so the next shot gets the same treatment.
Send Current Position
Report the position you are standing in when the module is switched off, so the server ends up where you actually are instead of wherever the buffer stopped. Has no effect on the releases that happen while running: every flush - the one at a shot, at a limit, and after you stop - already reports the current position, because that is what the release is for.
Rewind On Respawn
Drop the buffered movement when you respawn - recommended. When off, the buffer from before your death is kept instead and the module stops buffering, so it can be replayed later with csmcBlink.recall(). That reports the positions the buffer was recorded at without reporting where you just respawned, which drags you back to where you died instead of leaving you at the spawn point. Needs a server that accepts the old position as authoritative.
Release When Stopped Delay, ticks:
Release the buffer after this many ticks of standing in one place, so the box comes back onto you. 5 ticks is a quarter of a second. This does not touch the flush that fires on a shot - that one always runs, and with it the server is told your position before the shot leaves whether you were moving or not. Turn this off to keep the leftover offset while standing still.
Limit, packets: Limit, blocks:
Caps how far the buffer may drift from the server position. When one is passed the buffer is released and buffering continues from where the server now is, so the module keeps running instead of ending the session. 0 disables the limit. A very long buffer has to be replayed in a single tick by the server and looks like a teleport to everyone else, which is what this protects against.
Debug Box
Draws a box at the position the server believes you are at, plus a line from it to where you actually stand. Shown the whole time the module is enabled: while buffering the line is the drift the server sees, and when it is not buffering the box sits exactly on top of you - which is how you confirm the tracked position is still correct. Drawn through walls.
Debug Logging
Writes one line per second to the game log: how many movement packets were held versus let through, how many times the buffer was released, the current buffer size, the drift, and a count of the packet types that went out. Use it when the debug box does not behave as expected - held/s should climb while you move, and the packet list tells you which outgoing packets are actually there, so a fire packet can be picked out from it.
